# Hyprland Crash Investigation Session
# Machine: Real hardware (HP laptop)
# Distribution: Debian (later clarified to be Debian Unstable / Sid)
# Session Summary: COMPLETE INVESTIGATION CONTEXT

================================================================================
1. INITIAL PROBLEM
================================================================================

Symptoms:

- Running:

    start-hyprland

  immediately exits.

Originally it appeared as

    Segmentation fault

The user also noticed another symptom:

- After attempting to launch Hyprland they could no longer switch VTs using

    Ctrl+Alt+Fn

nor

    sudo chvt N

This made it initially appear that the crash might be locking the virtual console.

================================================================================
2. FIRST OBSERVATIONS
================================================================================

Initial startup log:

Hyprland starts normally and initializes many internal managers.

Observed sequence:

Old rlimit
New rlimit
Create EventLoopManager
Create KeybindManager
Create AnimationManager
Create DynamicPermissionManager
Create ConfigManager
Read hyprland.conf
Create ErrorOverlay
Create LayoutManager
Create TokenManager
Create PointerManager
Create EventManager
Create AsyncResourceGatherer

Immediately after this:

Segmentation fault

At this stage there was no obvious reason.

Possibilities considered:

- graphics driver
- configuration
- launcher bug
- xkb warnings
- DRM failure

================================================================================
3. XKB WARNINGS
================================================================================

The console showed messages like

Unsupported maximum keycode
Virtual modifier multiply defined
FK23 redefined
FK24 redefined

Conclusion:

These are generated by xkbcomp.

They are explicitly followed by

    Errors from xkbcomp are not fatal to the X server

Therefore they are unrelated.

Result:

Ignored.

================================================================================
4. VIRTUAL TERMINAL INVESTIGATION
================================================================================

User reported:

Ctrl+Alt+Fn
does nothing.

Suggested commands:

sudo chvt 10

sudo chvt 11

No visible effect.

Then checked:

tty

Output:

/dev/pts/6

Observation:

This is NOT a Linux virtual terminal.

It is a pseudo terminal.

That explained why:

fgconsole

returned

Couldn't get a file descriptor referring to the console

Meaning:

The shell itself is attached to a pts.

================================================================================
5. loginctl INVESTIGATION
================================================================================

Command:

loginctl session-status

Output showed:

Seat:
seat0

VC:
vc8

TTY:
pts/6

Type:
tty

Interpretation:

The login session belongs to VC8.

But the shell itself lives inside pts/6.

So

tty

and

loginctl

are reporting different things because one reports the controlling PTY while the
other reports the owning login session.

This is normal.

================================================================================
6. start-hyprland IDENTIFICATION
================================================================================

Initially suspected:

Maybe start-hyprland is a shell script.

Checked:

type start-hyprland

Output:

/usr/bin/start-hyprland

Attempted:

cat /usr/bin/start-hyprland

Screen filled with garbage.

Reason:

It is NOT a script.

It is a binary ELF executable.

Verified using:

file /usr/bin/start-hyprland

Result:

ELF 64-bit PIE executable

Therefore:

Launcher itself is a compiled program.

================================================================================
7. LIBRARY CHECK
================================================================================

Executed:

ldd /usr/bin/start-hyprland

All required libraries were found.

No missing shared library.

Therefore:

Crash is NOT caused by a missing dependency.

================================================================================
8. RUNNING HYPRLAND DIRECTLY
================================================================================

Instead of

start-hyprland

user executed

Hyprland

This was extremely useful.

Instead of immediately seeing only

Segmentation fault

Hyprland now printed its real exception.

================================================================================
9. TRUE FAILURE DISCOVERED
================================================================================

This was the turning point.

Actual error:

terminate called after throwing an instance of

std::runtime_error

what():

CBackend::create() failed!

Immediately afterwards:

Hyprland has crashed :(

================================================================================
10. IMPORTANT DISCOVERY
================================================================================

This changes the interpretation completely.

Originally it looked like

Segmentation fault

was the real bug.

Now we know:

NO.

The first failure is

CBackend::create()

The later segmentation fault happens while Hyprland is already crashing.

Meaning:

Primary failure:

Backend creation failed.

Secondary failure:

Crash reporter/logger crashes while printing the error.

================================================================================
11. GDB INVESTIGATION
================================================================================

Installed / launched:

gdb --args /usr/bin/start-hyprland

Executed:

run

Crash occurred.

Backtrace showed:

SIGSEGV

inside

std::__format::_Sink...

and

Hyprutils::CLI::CLogger

Functions included:

std::__format

Hyprutils::CLI::CLogger

libhyprutils.so

libstdc++

NOT:

renderer

NOT:

OpenGL

NOT:

Mesa

Interpretation:

Logger crashes after exception.

Not the original bug.

================================================================================
12. WHAT THE BACKTRACE TELLS US
================================================================================

Backtrace location:

std::format

↓

Hyprutils logger

↓

printing error

↓

segmentation fault

Meaning:

Program already failed.

Now logger is formatting text.

Logger crashes.

Therefore:

Backtrace does NOT identify the root cause.

It identifies crash during error reporting.

================================================================================
13. WHAT CBackend::create() DOES
================================================================================

This is currently the most important clue.

Backend creation includes:

Opening DRM

Finding GPU

Creating renderer

Creating GBM

Connecting libseat

Acquiring session

Initializing wlroots / Aquamarine backend

Any of these failing causes

CBackend::create()

to throw.

17. CURRENT WORKING THEORY
================================================================================

The investigation currently points toward:

Backend initialization failure.

NOT

renderer crash.

NOT

configuration.

NOT

Hyprland startup logic.

Likely sequence:

Hyprland starts

↓

Creates managers

↓

Reads config

↓

Attempts backend creation

↓

Aquamarine / wlroots backend initialization fails

↓

throws std::runtime_error

↓

Logger formats exception

↓

Logger itself crashes inside std::format

↓

SIGSEGV appears

↓

Program exits
